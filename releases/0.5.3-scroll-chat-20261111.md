# Orion 0.5.3 — voice and text conversation reveal

11 November 2026. Apple Silicon, Medium transcription edition.

Compact Chat now opens on the voice scene while a call is active. There is no
empty chat section below it. Sending a typed prompt reveals only that prompt's
measured height and normal padding, bounded by the available window. A reply
adds a New reply cue without growing the panel automatically.

Scrolling down grows the whole panel upward, keeping the composer and controls
anchored at the bottom, and gradually gives the space to the conversation. Once
expanded, messages scroll normally. Upward scrolling reaches the first message
before a further upward gesture shrinks the panel back to voice. Voice,
Conversation and New reply buttons, plus keyboard navigation, provide equivalent
access. Long prompts remain readable in short windows and reduced motion avoids
animated button transitions. The call, typed draft and research owner remain
mounted through collapse, note navigation and full Chat.

The worker queue and its counts are removed from the interface. Findings,
citations, saved-note links and actionable failures join the conversation.
Interim findings remain collapsed until opened; completed answers are directly
readable. Read aloud, Discuss by voice, Keep as note and retry actions remain
available with their existing scope and revision checks. Voice options contains
View conversation, Stop research and Clear voice chat. Clear still requires its
existing confirmation and leaves saved notes and typed Chat intact.

The change is presentation only: research scheduling, provider authority, note
review, persistence and autosave are preserved. Per-frame scroll work updates
local CSS. Audio animation frames do not rerender retained Markdown/citation
views, including while Chat is collapsed.

Validation: `npm run check` passed with 2,972 renderer tests and one existing
skip. Native Rust passed 222 tests with one existing ignore; MCP Rust passed 114.
Both Cargo format checks and the whitespace check passed. Browser checks used
production components with isolated transports at normal, narrow and short
window sizes, in dark and light modes. Checks covered measured prompt sizing,
reply arrival without growth, native scroll boundaries, keyboard access, one
retained call, saved-result links and first-ever opening directly to a finding.
A fresh-page console check had no warnings or errors. Development hot-refresh
warnings are retained in the evidence; they did not recur on a fresh load.

Browser QA used simulated voice/research transport, without actual microphone,
provider requests or user-vault changes. Live audible interaction is not claimed.

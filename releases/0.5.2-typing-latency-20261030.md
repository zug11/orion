# Orion 0.5.2 — native writing responsiveness

30 October 2026. Apple Silicon, Medium transcription edition.

This build addresses two native costs that remained after the earlier
Space-summary maintenance update. Ordinary autosave remains enabled.

- The workflow, editor context, editor actions, edit-review and voice
  work-order heartbeat commands move vault parsing and lock waits off the
  AppKit input thread onto blocking background workers. Fresh authorization,
  revision checks, window/session ownership and Space boundaries remain intact.
- The native formatting toolbar reuses its existing artwork during ordinary
  prose edits and save-status changes. Controls and inherited appearance still
  repaint; layout and overlay changes update geometry without PNG encoding.
  Overlapping image options inside the prose retain the ordinary HTML fallback.
- Pending control repaint survives immediate scroll updates. Existing More
  menu, ruler, accessibility fallback and stale-response handling remain intact.
- The prior summary idle scheduling and note-digest reuse improvements are
  included. Autosave still runs after an 800 ms pause with a five-second ceiling
  during continuous input. No storage migration or Done-only saving is introduced.

The application version remains 0.5.2. The final installer label is
`0.5.2-typing-latency-20261030-r2.m`.

## Verification

- Full renderer suite: 2,918 passed; one existing skipped test. Production build
  passed. The added regression verifies that 12 text insertions and a save-status
  update trigger zero redundant toolbar paints; the previous implementation
  triggered 13. Control/theme changes and overlapping image options are checked.
- Native tests: 222 passed; one existing ignored test. Connector tests: 114 passed.
- Both Cargo formatting checks and whitespace checks passed.
- Production browser checks at normal and narrow widths covered typing,
  autosave before Done, reload recovery, Undo/Redo and More formatting. No
  browser console errors were reported.
- Native runtime comparison used the same note and the actual 13,711,789-byte
  library. In an eight-second idle-editor sample, the prior installed build had
  318 of 5,567 main-thread samples inside vault reading (5.71%). The final build
  had zero of 6,060; vault reads appeared on background workers instead.
- Native toolbar and menu were visually inspected; normal Quit completed.
  Content hashes confirmed all 729 note titles and bodies unchanged after the
  desktop verification.

The native sample verifies removal of the demonstrated background-read stalls
from the UI thread. It is not an end-to-end keystroke latency benchmark and does
not establish that every possible source of writing latency is gone. Whole-vault
autosave remains and was not replaced by an incremental storage migration.

Detailed evidence is in `outputs/qa/typing-latency-20261030/`.
